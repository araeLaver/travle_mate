## 1. 로그인 세부정보 (`/app-content/testing-credentials`)

**앱에 제한된 부분이 있나요? → 예**

로그인 없이는 인증 화면 외에 아무것도 볼 수 없다.

| 필드 | 값 |
|---|---|
| 이름 | 전체 앱 |
| 사용자 이름 | `qa-check-20260913@example.com` |
| 비밀번호 | (이 계정을 만들 때 쓴 값) |

계정이 살아있는지 확인하려면:

```bash
curl -s -o /dev/null -w "%{http_code}\n" --max-time 120 \
  -X POST https://fryndo-untab-f93a6aa7.koyeb.app/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"qa-check-20260913@example.com","password":"<비밀번호>"}'
```

**기타 안내란에 반드시 적을 것:**

> 백엔드가 무료 호스팅이라 일정 시간 요청이 없으면 절전 상태가 됩니다.
> 첫 로그인 요청은 최대 60초까지 걸릴 수 있으니 기다려 주세요. 이후 요청은 1~2초입니다.

이걸 안 적으면 "앱이 응답하지 않는다"로 반려될 수 있다.

> ⚠️ **이 선언이 `타겟층 및 콘텐츠`를 막고, 타겟층이 다시 `데이터 보안` 제출을 막는다.**
> 셋은 반드시 이 순서로만 풀린다.

시작 시 **이메일 주소**를 묻는다 → `kdowndan@gmail.com` (입력 완료)
**카테고리 → 소셜 또는 커뮤니케이션** (선택 완료)

| 도박 | 아니요 | 없음 |

| **사용자 간 상호작용/소통** | **예** | 그룹 채팅 (`ChatRoomScreen`, `/chat/rooms/*`) |
| **사용자가 위치를 공유할 수 있나요** | **예** | 채팅에서 위치 전송 (`handleSendLocation`), 주변 사용자 매칭 |
| **사용자 생성 콘텐츠를 공유** | **예** | 채팅 메시지, 프로필 자기소개, 프로필 사진 |

## 4. 데이터 보안 — 입력 완료, 제출만 남음

### 수집·공유 여부

- **수집하나요 → 예**
- **제3자와 공유하나요 → 아니요**
  (Sentry DSN은 플레이스홀더라 비활성, 모바일에 광고·분석 SDK 없음)
- **전송 중 암호화 → 예** (모든 API가 HTTPS)
- **계정 생성 방법 → 사용자 이름 및 비밀번호 + OAuth**
  (`GoogleAuthButton.tsx`, `socialAuthService.ts` — 구글 로그인이 실제로 붙어 있다)
- **계정 삭제 URL → `https://fryndo-web.vercel.app/account-deletion`**
- **계정을 삭제하지 않고 일부 데이터만 삭제 → 아니요** (앱은 전체 삭제만 지원)

### 수집 항목 (Play 분류 기준으로 실제 입력한 값)

| Play 데이터 유형 | 필수/선택 | 목적 | 근거 |
|---|---|---|---|
| 이름 | 필수 | 앱 기능, 계정 관리 | 닉네임 — 회원가입 필수 |
| 이메일 주소 | 필수 | 앱 기능, 계정 관리 | 회원가입·로그인 |
| 사용자 ID | 필수 | 앱 기능, 계정 관리 | 내부 id |
| 기기 또는 기타 ID | 필수 | 앱 기능, 계정 관리 | refresh token의 deviceId |
| 앱 상호작용 | 필수 | 앱 기능 | `lastActivityAt`, 매칭·신뢰도 활동 기록 |
| 기타 정보 | 선택 | 앱 기능 | 나이·성별 (동행 추천) |
| 대략적인 위치 | 선택 | 앱 기능 | `getDeviceLocation`, `/nft/nearby` |
| 정확한 위치 | 선택 | 앱 기능 | `ACCESS_FINE_LOCATION` |
| 기타 인앱 메시지 | 선택 | 앱 기능 | `chat_messages` |
| 사진 | 선택 | 앱 기능 | `expo-image-picker` 프로필 사진 |
| 기타 사용자 제작 콘텐츠 | 선택 | 앱 기능 | 프로필 자기소개 |

모두 **수집됨 = 예 / 공유됨 = 아니요 / 임시 처리 = 아니요**(DB에 영구 저장)로 입력했다.

**체크하지 않은 것**: 결제 정보, 주소, 주소록, 통화 기록, SMS, 캘린더, 설치된 앱,
검색 기록, 웹 방문 기록, 건강·피트니스, 비정상 종료 로그·진단.

> **전화번호는 일부러 빼두었다.** `PhoneVerification.tsx`가 있지만 **웹 프로필에만** 붙어 있고
> 안드로이드 앱에는 입력란이 없다. 이 선언은 앱 기준이므로 넣지 않았다.
> **모바일에 전화번호 입력을 추가하면 이 선언을 반드시 고쳐야 한다.**

## 5. 금융 기능

**아무것도 체크하지 않음.**

특히 **"토큰화된 디지털 애셋(NFT) 판매·거래·보상"을 체크하지 말 것.** 근거:

- 앱에 지갑·민팅 버튼·마켓플레이스·경매 화면이 없다 (NFT 관련 화면은 `CollectionScreen` 하나)
- `nftService.requestMinting()`은 어느 화면에서도 호출되지 않는 죽은 코드
- 백엔드의 `MarketplaceController`·`AuctionController`를 앱이 한 번도 부르지 않는다
- 프로덕션은 블록체인 비활성 (`BLOCKCHAIN_REQUIRE_IN_PROD=false`, 기동 로그 "온체인 민팅 불가")
- 포인트는 구매도 현금화도 불가능한 인앱 숫자

2026-09-19에 앱 UI에서 "NFT·민팅" 표현도 걷어냈다(커밋 `b8ea811`).
**나중에 온체인 민팅을 켜면 이 선언을 다시 해야 한다.**

## 계정 삭제 구현 메모 (2026-09-20)

`UserService.deleteUser()`는 원래 `is_active = false`만 설정했다. 아무것도 지우지 않으므로
데이터 보안에 "삭제 요청 가능 = 예"를 선언하면 허위 선언이 된다. 다음과 같이 바꿨다.

- 이메일·닉네임을 식별 불가능한 플레이스홀더로 치환 (unique 제약 때문에 null 불가)
- 이름·나이·성별·자기소개·프로필 사진·여행스타일·관심사·언어·위치·전화번호·FCM 토큰·
  소셜 providerId를 전부 제거
- 비밀번호를 난수로 덮어써 복구 불가능하게 만듦
- `refreshTokenRepository.revokeAllByUser()`로 열려 있던 세션 즉시 종료
- `deletionRequestedAt` 기록
- `AuthService.login()` / `refreshToken()`이 비활성 계정을 거부

행 자체는 남긴다. `group_members` · `chat_messages` · `user_reviews`가 `user_id`를 외래키로
잡고 있어 하드 삭제하면 **다른 사용자의 여행 기록이 깨진다.** Play 정책이 요구하는 것은
개인정보의 실제 제거이지 행의 물리적 삭제가 아니다. 이 구분과 보관 기간은
`/account-deletion` 페이지에 그대로 공개해 두었다.
